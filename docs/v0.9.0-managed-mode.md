## 3. 后端设计（Phase A）

### 3.1 仓库

- 名字：`typeanything-backend`
- 可见性：**private**
- 部署：Cloudflare Workers + KV namespace

### 3.2 目录结构

```
typeanything-backend/
├── src/
│   ├── worker.ts        # 入口 fetch handler
│   ├── auth.ts          # HMAC 验证 + 机器码解码
│   ├── quota.ts         # KV 读写 + 限流
│   ├── proxy.ts         # 透传 DS + token 计数
│   └── error.ts         # 错误响应统一化
├── test/
│   └── worker.test.ts   # vitest
├── wrangler.toml
├── package.json
└── README.md
```

### 3.3 KV schema

```ts
// KV namespace: TA_QUOTA
type QuotaEntry = {
  used:  number;   // 本月已用 token
  limit: number;   // 本月上限（free=5000, paid=∞）
  plan:  "free" | "paid";
  first_seen: number;  // unix ts, 首次出现时间
};

// key 格式：ta:quota:<sha256(machine_code)>:<YYYY-MM>
// TTL：到下月 1 日自动过期清空
```

### 3.4 鉴权协议

**客户端发出的 Authorization header**：
```
Authorization: Bearer <machine-code-hmac>
```

`machine-code-hmac` = `base64( HMAC-SHA256(machine_code_raw, SHARED_SECRET) )`

`machine_code_raw` = `SHA256(VolumeID + MachineGuid)`（在客户端机器上）

`SHARED_SECRET` 写在客户端二进制里（混淆但不算秘密——这是反作弊的第一道门，不是最后一道）。后端用同样的 SECRET 校验。

**反作弊层**（按优先级）：
1. HMAC 校验：阻挡随机 token 请求
2. 月度配额：单机器码 5000 token / 月
3. 日额度：单机器码 200 token / 日（避免单日刷爆）
4. IP 限流：同 IP 60 req / 分钟（Cloudflare Worker 原生支持）
5. 黑名单：发现滥用模式手动加 KV `ta:banned:<hmac>` → 直接 403

### 3.5 接口契约

**正常请求**：

```
POST https://ta.hrdai.com/v1/chat/completions
Headers:
  Authorization: Bearer <hmac>
  Content-Type: application/json
  X-TA-Version: 0.9.0
Body: { OpenAI Chat Completions 兼容 payload }
```

**响应**：

| status | 含义 | 客户端行为 |
|---|---|---|
| 200 | 正常透传 DS 响应 | 替换中文 |
| 401 | HMAC 不对 | 写 log + 不替换（少见，可能客户端被改） |
| 402 | 月配额跑完 | 弹「免费额度已用完，升级订阅」toast，不替换 |
| 429 | 限流 | 弹「调用过于频繁，请稍后再试」 |
| 5xx | 后端 / DS 故障 | 弹「AI 服务暂时不可用，请稍后再试」 |

**响应头额外字段**（供客户端展示配额）：
- `X-TA-Quota-Used: 1623`
- `X-TA-Quota-Limit: 5000`
- `X-TA-Quota-Reset: 1751331600`（unix ts，月初）

### 3.6 透传策略

后端 **不修改** payload body（用户的中文 prompt 全文透传给 DS）。**不存任何 prompt 内容**（不写 log、不持久化）。

KV 只记 token 用量数字。日志只记：
- 机器码 HMAC 前 8 位
- 时间戳
- token 用量（input/output 数字）
- 响应 status

**不记**：prompt 文本、响应文本、IP（CF 自动 IP log 由 Cloudflare 保留 30 天，我们不二次存储）。

### 3.7 部署

- 域名：`ta.hrdai.com`（需要购买 / 解析 / 接 Cloudflare）
- DS 账号：单独 API key，充值 ¥100 起步
- 监控：Cloudflare Analytics + 自定义指标推 `total_tokens / day` 到 Sentry / 自建 Grafana
- 回滚：Cloudflare Workers 一键回版本

### 4.3 客户端机器码生成

新文件 `tools/ta-settings/machine_code.cpp`：

```cpp
// machine_code = sha256( VolumeID(C:) + MachineGuid )
// 不含个人识别信息；同机器跨用户稳定。
std::string GetMachineCode();
// hmac = base64( HMAC-SHA256(machine_code, SHARED_SECRET) )
std::string GetMachineCodeHmac();
```

`SHARED_SECRET` 写死在二进制里，用简单字节移位混淆。**这不是真秘密**，反作弊靠服务端配额 + 黑名单。

### 4.4 processor.cc 改造

translate 路径里：

```cpp
std::string auth_token;
if (endpoint_ == "ta.hrdai.com") {
  // Managed mode — generate HMAC at request time, ignore api_key_.
  auth_token = GetMachineCodeHmac();
} else {
  // BYOK mode — passthrough user's api_key.
  auth_token = api_key_;
}
```

同时**删除** v0.8.x 的「api_key 空弹模型配置面板」和「401/403 弹面板」逻辑。Hybrid 之后这两条路径不再有用。

### 4.5 installer.cpp schema 默认值

写 `typeanything.schema.yaml` 时默认填：

```yaml
typeanything:
  api_key: ""                          # 留空 = 走机器码 HMAC
  model: deepseek-chat
  host: ta.hrdai.com
  path: /v1/chat/completions
  temperature: 0.3
```

如果 `%APPDATA%\Rime\typeanything.schema.yaml` 已存在（升级安装），**保留用户原值**——可能他配过 BYOK，不能覆盖。

## 8. 失败 / 降级路径

| 场景 | 用户体验 | 后端 / 客户端行为 |
|---|---|---|
| 后端完全挂 | 打字按 Enter → 几秒后弹「AI 暂不可用」toast，中文保留 | 客户端 timeout 5s，不删 buffer |
| 用户超日额度（200 token）| 立即弹「今日已用完，明日 0 点恢复」 | 后端返 429 + `Retry-After` |
| 用户超月额度（5000）| 弹「免费额度已用完，升级订阅 ¥9.9」+ 不替换中文 | 后端返 402 |
| 用户网络断 | 弹「网络异常，检查代理 / VPN」 | 客户端 WinHTTP 超时分支 |
| 机器码 HMAC 校验失败 | 弹「签名异常，请重新安装」+ 不替换 | 后端返 401 |
| 用户主动改 BYOK（schema） | 全部走自己的 endpoint，不经我们 | processor 看 host 字段切路径 |

所有失败路径**继续写 `typeanything_translate.log`** 给我们调试用。

## 9. 观测 / 数据采集

### 9.1 后端指标

每天聚合一次推 Grafana / 自建 dashboard：

- 唯一 HMAC（≈ MAU）
- 总请求数 / 总 token 数
- 跑过 50% 配额的用户数
- 跑满配额的用户数
- 平均 input / output token 数
- p50 / p95 / p99 延迟
- 错误率（按 status code 分桶）

### 9.2 客户端指标

**不主动上报任何 telemetry**。所有数据从后端日志反推。

理由：信任 + 简单。Profile B / C 用户对客户端 telemetry 极度敏感，会写 issue 骂街。

唯一例外：crash dump 如果实现，必须默认 opt-out + 文档明确说明上传内容。

### 9.3 转化漏斗

未来要看的：
- 装机 → 首次翻译（关键指标）
- 首次翻译 → 当月第 10 次翻译（留存信号）
- 跑过限额 → 点击「升级订阅」（付费意向）
- 点击升级 → 实际付费（v1.0.0 后才有）

## 10. 安全模型

### 10.1 威胁模型

| 威胁 | 危害 | 应对 |
|---|---|---|
| 普通用户瞎请求 | 浪费 token | HMAC + 配额 |
| 脚本 kiddy 用客户端机器码刷大量 | 单机刷爆 | 日配额 + IP 限流 |
| 提取 SHARED_SECRET 生成无限 HMAC | 后端无限制收请求 | KV 黑名单 + IP 限流 + 异常模式自动封 |
| 后端 worker 被攻陷 | 用户输入泄漏 | KV / 日志不存 prompt 内容 |
| DS 账号 key 泄漏 | 第三方刷我们的 DS 账户 | DS key 只在 Worker secrets，不进代码仓库；Worker 出向 IP 白名单 |
| 客户端被反编译 / 改 host | 用户走自己的 BYOK | 这是 feature 不是 bug |

### 10.2 我们承诺

- **后端日志保留 7 天**自动清
- **不存 prompt 内容**到任何持久化层
- **客户端开源**，用户可审计
- **BYOK 永远可用**，用户随时可切
